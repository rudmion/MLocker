# Tauri Updater Plugin — Интеграция

## Цель
Заменить кастомный обновлённый механизм на официальный плагин `tauri-plugin-updater`. Автопроверка при запуске + уведомление, passive установка на Windows.

## Изменения

### 1. Генерация ключей подписи
Сгенерировать ключевую пару minisign. Публичный ключ пойдёт в конфиг, приватный — в секреты GitHub Actions (уже настроены `TAURI_SIGNING_PRIVATE_KEY` и `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`).

```bash
npx tauri signer generate -w ~/.tauri/mlocker.key
```

### 2. `src-tauri/Cargo.toml` — добавить зависимости
```toml
tauri-plugin-updater = { version = "2", target = 'cfg(any(target_os = "macos", windows, target_os = "linux"))' }
tauri-plugin-process = "2"
```

### 3. `src-tauri/tauri.conf.json` — конфиг плагина
Добавить в `bundle`:
```json
"createUpdaterArtifacts": true
```

Добавить в `plugins`:
```json
"updater": {
  "pubkey": "<СОДЕРЖИМОЕ pubkey.pem>",
  "endpoints": [
    "https://github.com/rudmion/MLocker/releases/latest/download/latest.json"
  ],
  "windows": {
    "installMode": "passive"
  }
}
```

### 4. `src-tauri/src/main.rs` — регистрация плагинов
Добавить в builder:
```rust
.plugin(tauri_plugin_updater::Builder::new().build())
.plugin(tauri_plugin_process::init())
```

### 5. `src-tauri/capabilities/default.json` — права
Добавить в `permissions`:
```json
"updater:default"
```

### 6. `package.json` — JS зависимости
```bash
yarn add @tauri-apps/plugin-updater @tauri-apps/plugin-process
```

### 7. `src/hooks/useUpdateChecker.ts` — НОВЫЙ ФАЙЛ
React-хук для управления состоянием обновлений:
- `check()` — вызывает `check()` из `@tauri-apps/plugin-updater`
- `downloadAndInstall()` — скачивает и устанавливает с колбэком прогресса
- `restart()` — вызывает `relaunch()` из `@tauri-apps/plugin-process`
- Состояния: `idle → checking → hasUpdate → downloading → installing → installed`
- Автопроверка при маунте (тихая, без уведомлений)

### 8. `src/components/update/UpdateNotification.tsx` — НОВЫЙ ФАЙЛ
Компонент уведомления (в правом нижнем углу):
- Показывает когда `hasUpdate === true`
- Отображает: текущая → новая версия, changelog из `update.body`
- Кнопки: «Обновить» (запускает скачивание+установку), «Позже» (скрывает)
- Прогресс-бар во время скачивания
- Кнопка «Перезапустить» после установки

### 9. `src/components/settings/SettingsDialog.tsx` — кнопка в настройках
Добавить кнопку «Проверить обновления» в секцию «О приложении»:
- Вызывает ручную проверку через хук
- Показывает спиннер во время проверки
- Если обновление найдено — показывает версию и кнопку «Обновить»

### 10. `src/App.tsx` — интеграция
- Импортировать `useUpdateChecker`
- Передать в `SettingsDialog` пропсы для ручной проверки
- Рендерить `<UpdateNotification>` когда `hasUpdate && masterState === 'unlocked'`

### 11. `.github/workflows/release.yml` — CI/CD
- Обновить `tauri-apps/tauri-action@v0` → `tauri-apps/tauri-action@v1`
- Добавить `tagName: v__VERSION__` и `releaseName: 'MLocker v__VERSION__'`
- `TAURI_SIGNING_PRIVATE_KEY` и `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` уже настроены как secrets
- tauri-action@v1 автоматически генерирует `latest.json` и `.sig` файлы

## Верификация
1. `cargo check` — Rust компилируется
2. `npx tsc --noEmit` — TypeScript компилируется
3. `yarn tauri dev` — приложение запускается, хук проверяет обновление при маунте
4. В настройках появляется кнопка «Проверить обновления»
5. При наличии обновления показывается уведомление с прогрессом

# Аудит: Критические моменты и советы

## КРИТИЧЕСКИЕ (требуют исправления)

### C-1. Отсутствует `process:default` permission
**Файл:** `src-tauri/capabilities/default.json`
**Проблема:** Добавлено `updater:default`, но НЕ добавлено `process:default`. Функция `relaunch()` из `@tauri-apps/plugin-process` требует эту пермишн. Без неё кнопка «Перезапустить» после установки обновления **не сработает**.
**Исправление:** Добавить `"process:default"` в permissions.

### C-2. RELEASING.md содержит устаревшую информацию
**Файл:** `RELEASING.md`, строки 114-141
**Проблема:** Секция 6 описывает старый кастомный обновлённый механизм (`updater.rs`, `compare_versions()`, `update-progress` события), который больше не существует. Это вводит в заблуждение.
**Исправление:** Переписать секцию 6 с описанием нового механизма через `tauri-plugin-updater`.

### C-3. Окно шире (800) чем minWidth (900)
**Файл:** `src-tauri/tauri.conf.json`
**Проблема:** `width: 800` при `minWidth: 900` вызывает визуальный скачок при первом открытии.
**Исправление:** Изменить `width` на `900` или `minWidth` на `800`.

## ВЫСОКИЙ ПРИОРИТЕТ (рекомендуется)

### H-1. Нет периодической проверки обновлений
**Файл:** `src/hooks/useUpdateChecker.ts`
**Проблема:** Проверка только при запуске (через 3 сек). Если пользователь держит приложение открытым днями — обновления не увидит.
**Совет:** Добавить `setInterval` с интервалом ~6 часов для повторной тихой проверки.

### H-2. Нет отмены скачивания
**Файл:** `src/hooks/useUpdateChecker.ts`
**Проблема:** Если пользователь нажал «Позже» во время скачивания — загрузка продолжается в фоне. Состояние может перейти в `installed` после dismiss.
**Совет:** Добавить `AbortController` или флаг `dismissed` и проверять его в callback прогресса.

### H-3. Нет опции «Пропустить версию»
**Файл:** `src/components/update/UpdateNotification.tsx`
**Проблема:** Только «Обновить» и «Позже». Если пользователь не хочет обновляться именно до этой версии — его будут спамить каждое открытие.
**Совет:** Сохранять пропущенную версию в `localStorage` и не показывать уведомление для неё.

### H-4. Нет кодирования macOS и Windows (Authenticode)
**Файл:** `.github/workflows/release.yml`
**Проблема:** Нет настройки `APPLE_CERTIFICATE`, `WINDOWS_CERTIFICATE`. На macOS будет Gatekeeper warning, на Windows — SmartScreen. Для менеджер паролей это критично — пользователи не будут доверять.
**Совет:** Настроить кодирование для обеих платформ. Минимум — для macOS (Gatekeeper блокирует приложение полностью).

## СРЕДНИЙ ПРИОРИТЕТ

### M-1. CSP отключен (`null`)
**Файл:** `src-tauri/tauri.conf.json`
**Проблема:** Для менеджер паролей отсутствие CSP — уязвимость. Любой XSS может украсть пароли.
**Совет:** Включить CSP с разрешением только `asset:` протокола и `script-src 'self'`.

### M-2. Asset protocol scope `"**"` слишком широкий
**Файл:** `src-tauri/tauri.conf.json`
**Проблема:** Фронтенд может читать ЛЮБОЙ файл на диске через `asset://` протокол.
**Совет:** Ограничить scope только директорией данных приложения.

### M-3. `shell:allow-open` включен
**Файл:** `src-tauri/capabilities/default.json`
**Проблема:** Позволяет фронтенду открывать произвольные URL и программы.
**Совет:** Оставить только если нужно для функции открытия URL из записей паролей. Иначе убрать.

### M-4. Нет атомарных записей файлов
**Файл:** `src-tauri/src/main.rs`
**Проблема:** `std::fs::write` пишет напрямую в файл. Крэш во время записи = повреждение БД паролей.
**Совет:** Писать во временный файл, затем атомарно переименовать (write-to-temp-then-rename).
