# Plan: Fix update installing to wrong directory

## Problem
When the user installs MLocker to a custom path (e.g. `B:\Programs\Password App\`), the update process creates a duplicate at the default NSIS path (`C:\Users\Rudya\AppData\Local\MLocker\`). The NSIS `/D=` parameter is being ignored by the installer.

## Root Cause
NSIS installer built by Tauri ignores the `/D=` silent-install parameter, likely due to `InstallDirRegKey` or other NSIS directives that override it.

## Solution: Save install path to config file + use it during update

### Approach
1. On first app startup, detect the real install path via `std::env::current_exe().parent()` and save it to a JSON config file next to the executable (e.g. `install_path.json`)
2. On subsequent startups, read the saved path if it exists; if not, detect and save it
3. During update, read the saved path and pass it to NSIS via `/D=`
4. As a fallback, also try `current_exe().parent()` if the config file doesn't exist

### Files to modify

**`src-tauri/src/updater.rs`**
- Add `get_real_install_path()` helper that:
  1. Looks for `install_path.json` next to the running exe
  2. If found, reads and returns the saved path
  3. If not found, uses `current_exe().parent()`, saves it to `install_path.json`, and returns it
- Update `get_install_path` to use the new helper
- Update `install_downloaded_update` to use the new helper for the `/D=` parameter
- Add logging of the detected path for debugging

**`src-tauri/src/main.rs`**
- On app startup (in `main()`), call `std::env::current_exe().parent()` and save it to `install_path.json` next to the exe (if the file doesn't already exist)
- This ensures the path is captured even before any update check

### Verification
1. Build the app with `cargo build`
2. Install to a custom path
3. Verify `install_path.json` is created next to the exe
4. Trigger an update — verify NSIS receives the correct `/D=` path
5. Confirm no duplicate is created
