# Как работает обновление приложения MLocker

## Обзор

MLocker — это Tauri v2 десктопное приложение (React + TypeScript фронтенд, Rust бэкенд). Приложение использует **кастомную систему обновлений** через GitHub API, а не стандартный плагин Tauri Updater (хотя он зарегистрирован в конфиге).

---

## Полный цикл обновления

### 1. Запуск проверки

Обновление проверяется двумя способами:

- **Автоматически при запуске** — `useUpdateChecker.tsx` вызывает `checkForUpdate(false)` при монтировании компонента (бесшумно, без уведомлений)
- **Вручную** — пользователь нажимает кнопку "Check for updates" в `SettingsDialog.tsx`, что вызывает `checkForUpdate(true)` (с уведомлением "You have the latest version" если обновлений нет)

### 2. Проверка наличия обновления (backend)

**Файл**: `src-tauri/src/updater.rs`, команда `check_for_update`

1. Получает текущую версию из `app.package_info().version` (из `tauri.conf.json`)
2. Отправляет GET-запрос к `https://api.github.com/repos/rudmion/MLocker/releases/latest`
3. Если релиз найден (200):
   - Извлекает `tag_name`, убирает префикс `v`
   - Сравнивает версии через `compare_versions()` (поэлементное сравнение semver: major.minor.patch)
4. Если релизов нет (404): fallback на API тегов `/repos/rudmion/MLocker/tags` — проверяет первый тег
5. Возвращает структуру `UpdateInfo`:
   ```rust
   struct UpdateInfo {
       has_update: bool,
       current_version: String,
       latest_version: String,
       body: String,        // changelog
       html_url: String,    // ссылка на релиз
       download_url: String // URL скачивания инсталлера
   }
   ```

### 3. UI уведомление (frontend)

**Файлы**: `src/hooks/useUpdateChecker.tsx`, `src/components/update/UpdateDialog.tsx`

- Если `hasUpdate == true` → показывается `UpdateDialog` (AlertDialog):
  - Текущая и новая версия
  - Changelog в прокручиваемой области
  - Кнопки: "Later" (отложить) и "Update now" (установить)

### 4. Скачивание обновления

**Файл**: `src-tauri/src/updater.rs`, команда `download_update`

1. Принимает URL скачивания
2. Скачивает инсталлер через `reqwest` с потоковым чтением (streaming bytes)
3. Сохраняет во временную директорию (`%TEMP%`)
4. В процессе скачивания испускает события `update-progress` с прогрессом (`downloaded` / `total` байты)
5. Фронтенд (`useUpdateChecker.tsx`) слушает эти события и обновляет полосу прогресса в `UpdateDialog`
6. После завершения сохраняет путь к файлу в `pending_update.json` в директории данных приложения

### 5. Установка обновления

**Файл**: `src-tauri/src/updater.rs`, команда `install_downloaded_update`

1. Читает `pending_update.json` для получения пути к инсталлеру
2. Запускает инсталлер как отдельный процесс:
   - **Windows**: `installer.exe /S` (тихая установка NSIS)
   - **macOS**: `open -W installer.dmg`
   - **Linux**: `xdg-open installer.deb`
3. Очищает `pending_update.json`
4. NSIS-инсталлер заменяет файлы приложения и автоматически перезапускает его

### 6. UX после скачивания

**Файл**: `src/App.tsx`, `src/lib/notifications.tsx`

После завершения скачивания показывается persistent toast-уведомление (20 сек):
> "Update downloaded. Restart to install."

С кнопкой "Restart", которая вызывает `install_downloaded_update`.

## Процесс релиза (CI/CD)

1. Разработчик запускает `yarn bump <version>`:
   - Обновляет версию в 3 файлах: `package.json`, `tauri.conf.json`, `Cargo.toml`
   - Создаёт коммит: `chore: bump version to X.Y.Z`
   - Создаёт git tag: `vX.Y.Z`
   - Пушит коммит и тег
2. Push тега `v*` триггерит GitHub Actions workflow (`.github/workflows/release.yml`):
   - Параллельная сборка на 3 платформах: Windows (x86_64), macOS (aarch64), Linux (x86_64)
   - Использует `tauri-apps/tauri-action@v0` для сборки и создания GitHub Release
   - Подписывает бинарники через minisign (`TAURI_SIGNING_PRIVATE_KEY`)
   - Загружает артефакты (`.exe`, `.dmg`, `.deb`, `.AppImage`, `.rpm`) как assets релиза

## Два механизма обновления (замечание)

Приложение регистрирует **два** механизма обновления:

1. **Стандартный Tauri Updater Plugin** — настроен в `tauri.conf.json` с публичным ключом и эндпоинтом `latest.json`, зарегистрирован в `main.rs` через `.plugin(tauri_plugin_updater::Builder::new().build())`. Этот плагин **не используется** в реальном flow обновлений.

2. **Кастомный GitHub API Updater** (`updater.rs`) — **активно используемый** механизм. Напрямую обращается к GitHub API, скачивает инсталлер, запускает его.

Плагин `tauri-plugin-updater` зарегистрирован, но не вызывается — это потенциальная точка для очистки (удаления неиспользуемого кода).

## Потенциальные проблемы / моменты для улучшения

1. **Нет автоматического обновления** — обновление только по запросу пользователя (нет фоновой проверки по расписанию)
2. **Нет валидации подписи** — скачанный инсталлер не проверяется через minisign перед установкой (хотя ключ есть в конфиге)
3. **Дублирование кода** — стандартный Tauri updater plugin зарегистрирован, но не используется
4. **Race condition** — если пользователь закроет приложение во время скачивания, `pending_update.json` останется, но инсталлер не запустится
