# Исправление: дублирование экземпляра при обновлении

## Проблема

После автообновления NSIS-инсталлер создаёт второй экземпляр приложения вместо обновления текущего. Старое приложение продолжает работать.

## Корневая причина

Поток обновления (в `src-tauri/src/updater.rs:188-242`):

1. Фронтенд вызывает `install_downloaded_update`
2. Rust-код запускает NSIS-инсталлер (`/S` — тихая установка)
3. **Код сразу возвращает `Ok(())` — приложение НЕ закрывается**
4. NSIS пытается заменить файлы `.exe`, которые всё ещё заняты запущенным процессом
5. Windows либо блокирует замену (инсталлер молча падает), либо NSIS запускает новый экземпляр
6. `tauri-plugin-single-instance` не срабатывает, потому что NSIS перезапускает приложение через свой механизм, а не через Tauri

**Итог**: старое приложение живо + NSIS создало новый процесс = два экземпляра.

## Решение

В `install_downloaded_update` после запуска NSIS-инсталлера нужно **немедленно завершить приложение** (`app.exit(0)`), чтобы NSIS мог заменить файлы и перезапустить приложение самостоятельно.

## Изменения

### `src-tauri/src/updater.rs`

В функции `install_downloaded_update` (строки 188-242):

**Текущий код** (строки 213-218):
```rust
#[cfg(target_os = "windows")]
{
    std::process::Command::new(&file_path)
        .arg("/S")
        .spawn()
        .map_err(|e| format!("Failed to launch installer: {}", e))?;
}
```

**Новый код**:
```rust
#[cfg(target_os = "windows")]
{
    std::process::Command::new(&file_path)
        .arg("/S")
        .spawn()
        .map_err(|e| format!("Failed to launch installer: {}", e))?;
    // Give NSIS a moment to start, then exit so it can replace files
    std::thread::sleep(std::time::Duration::from_secs(2));
    app.exit(0);
}
```

Аналогично для macOS и Linux (если поддерживаются) — после `spawn()` добавить `app.exit(0)`.

### `src/hooks/useUpdateChecker.tsx`

Убрать不必要的 вызов `check_for_update` перед `download_update` в `installUpdate` (строки 124-127). Данные уже есть в state после первого `checkForUpdate`. Либо передавать `download_url` в `installUpdate` извне.

**Текущий код** (строки 123-129):
```typescript
const info = await invoke<UpdateInfo>('check_for_update');
if (!info.download_url) {
  throw new Error('Download URL not available');
}
await invoke<string>('download_update', { url: info.download_url });
```

**Новый код** — передавать URL через параметр:
```typescript
const installUpdate = useCallback(async (downloadUrl?: string) => {
  // ...
  const url = downloadUrl || state.downloadUrl; // хранить download_url в state
  if (!url) throw new Error('Download URL not available');
  await invoke<string>('download_update', { url });
  // ...
}, []);
```

Или проще — сохранять `download_url` в state при обнаружении обновления.

### `src/App.tsx`

После `notifications.updateInstalled(restartWithInstall)` — больше ничего делать не нужно. Приложение само закроется из Rust-кода. Уведомление "Перезагрузить" можно оставить как fallback (если NSIS не перезапустит автоматически).

### `src/lib/notifications.tsx`

Текст уведомления можно обновить:
```
'Обновление загружено. Приложение закроется для установки.'
```
Вместо:
```
'Обновление загружено. Перезагрузите для установки.'
```

## Что НЕ нужно менять

- `tauri-plugin-single-instance` — он уже настроен, просто не мог сработать из-за гонки
- NSIS-флаги — `/S` достаточен, NSIS remembers install path из реестра
- `tauri-plugin-updater` — кастомный GitHub API updater работает корректно для скачивания

## Верификация

1. Собрать приложение: `yarn build` → `cargo tauri build`
2. Установить версию N
3. Запустить, проверить что работает
4. Создать релиз с версией N+1 через `npm run bump -- <version>` + git tag
5. Запустить версию N, дождаться обновления
6. Нажать "Обновить" → NSIS запустится → приложение закроется → NSIS заменит файлы → NSIS перезапустит приложение
7. Проверить: только один экземпляр, версия N+1
