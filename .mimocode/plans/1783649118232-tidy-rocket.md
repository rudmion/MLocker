# Пошаговая инструкция по релизу MLocker

## Текущее состояние

- Версия приложения: `0.2.0` (в `package.json`, `tauri.conf.json`, `Cargo.toml`)
- Ветка: `development`
- GitHub Actions workflow настроен (`.github/workflows/release.yml`)
- Скрипт синхронизации версий готов (`scripts/bump-version.cjs`)

---

## Первый релиз (сейчас)

Вы впервые запускаете процесс релиза. Нужно сделать подготовку и первый релиз.

### Шаг 1: Сгенерировать ключ подписи (один раз)

Откройте терминал и выполните:

```bash
npx tauri signer generate -w ~/.tauri/mlocker.key
```

Система спросит пароль — придумайте и запишите его. Он понадобится для GitHub Secrets.

После выполнения вы увидите публичный ключ. Скопируйте его — он уже вставлен в `tauri.conf.json`.

### Шаг 2: Добавить секреты в GitHub

1. Перейдите на https://github.com/rudmion/MLocker/settings/secrets/actions
2. Нажмите "New repository secret"
3. Добавьте два секрета:

| Имя | Значение |
|-----|----------|
| `TAURI_SIGNING_PRIVATE_KEY` | Содержимое файла `~/.tauri/mlocker.key` |
| `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` | Пароль, который вы указали при генерации |

### Шаг 3: Создать ветку release

```bash
git checkout -b release
git push -u origin release
```

### Шаг 4: Запушить текущий код в release

Все изменения уже сделаны (updater, workflow, скрипт). Запушьте их:

```bash
git add .
git commit -m "feat: add auto-updater and release workflow"
git push origin release
```

### Шаг 5: Создать первый релиз

Текущая версия `0.2.0`. Создайте тег:

```bash
git tag v0.2.0
git push origin v0.2.0
```

GitHub Actions автоматически:
- Соберёт приложение для Windows, macOS, Linux
- Подпишет артефакты
- Создаст Release на GitHub
- Загрузит `.msi`, `.exe`, `.dmg`, `.AppImage` и `latest.json`

### Шаг 6: Проверить

1. Перейдите на https://github.com/rudmion/MLocker/releases
2. Убедитесь что релиз `v0.2.0` создан с артефактами
3. Убедитесь что файл `latest.json` загружен

## Процесс обновления (последующие релизы)

Когда вы внесёте изменения и захотите выпустить новую версию:

### Шаг 1: Внести изменения

Работайте как обычно в `development` ветке:

```bash
git checkout development
# ... делайте изменения ...
git add .
git commit -m "feat: описание изменений"
git push origin development
```

### Шаг 2: Обновить версию

```bash
npm run bump -- 0.3.0
```

Скрипт автоматически обновит версию в:
- `package.json`
- `src-tauri/tauri.conf.json`
- `src-tauri/Cargo.toml`

### Шаг 3: Запушить изменения версии

```bash
git add .
git commit -m "chore: bump version to 0.3.0"
git push origin development
```

### Шаг 4: Синхронизировать release ветку

```bash
git checkout release
git merge development
git push origin release
```

### Шаг 5: Создать тег и запустить релиз

```bash
git tag v0.3.0
git push origin v0.3.0
```

GitHub Actions соберёт и опубликует релиз автоматически.

### Шаг 6: Вернуться к разработке

```bash
git checkout development
```

## Версионирование

Используйте формат `X.Y.Z`:
- **X** (мажорная) — крупные изменения, ломающая совместимость
- **Y** (минорная) — новые функции, обратно совместимые
- **Z** (патч) — исправления багов

Примеры:
- `0.1.0` → `0.2.0` (новая функция)
- `0.2.0` → `0.2.1` (исправление бага)
- `0.2.1` → `1.0.0` (первая стабильная версия)

## Что происходит "под капотом"

```
git tag v0.3.0 && git push origin v0.3.0
        │
        ▼
GitHub Actions (release.yml)
        │
        ├── Windows: сборка .msi + .exe
        ├── macOS: сборка .dmg
        └── Linux: сборка .AppImage
        │
        ▼
Создаётся GitHub Release v0.3.0
        │
        ├── Загружены артефакты
        └── Загружен latest.json
        │
        ▼
Приложение при запуске
        │
        ├── GET /repos/rudmion/MLocker/releases/latest
        ├── Сравнение версий
        └── Показ диалога обновления
```

## Частые ошибки

| Проблема | Решение |
|----------|---------|
| Версия в `package.json` и `tauri.conf.json` разная | Используйте `npm run bump` вместо ручного редактирования |
| GitHub Actions не запускается | Проверьте что тег начинается с `v` (например, `v0.3.0`) |
| Ошибка подписи | Проверьте что `TAURI_SIGNING_PRIVATE_KEY` добавлен в GitHub Secrets |
| Нет `latest.json` в релизе | tauri-action генерирует его автоматически, проверьте логи workflow |
| Приложение не показывает обновление | Убедитесь что версия на GitHub выше текущей в приложении |
