# Plan: Add fallback icon for missing entry icons

## Problem

After reinstalling MLocker, all downloaded favicons are gone from disk (they were in `AppData/my-password-manager/favicons/`), but `data.json` still stores the old absolute paths in `iconUrl`. The frontend uses `convertFileSrc(iconUrl)` which produces `asset://localhost/C:/.../deleted.png` — the browser fails to load it, showing a broken image. There is no `onError` handler on any `<img>` tag to fall back to the default icon.

## Current behavior

- If `iconUrl` is `null` or `''` → fallback SVG is shown (correct)
- If `iconUrl` points to a missing file → broken image (broken)

## Solution

Add `onError` event handlers to all `<img>` tags that render entry icons. On error, swap the `src` to the default icon (`/material-icon-theme_folder-docs.svg`).

## Files to modify

### 1. `src/components/content/Records.tsx` (lines 152-164)
Add `onError` handler to the `<img>` tag in the records list.

### 2. `src/components/header/CommandMenu.tsx` (lines 53-57)
Add `onError` handler to the `<img>` tag in the command menu search results.

### 3. `src/components/inspector/InspectorHeader.tsx` (lines 19-27)
Add `onError` handler to the `<img>` tag in the inspector panel header.

## Implementation pattern

For each `<img>` tag, add:
```tsx
onError={(e) => {
  (e.target as HTMLImageElement).src = '/material-icon-theme_folder-docs.svg';
}}
```

This is the simplest and most reliable approach — no state management needed, no extra imports. The browser fires `onError` when the `asset://` URL fails to resolve to a file on disk, and we swap the src to the bundled default SVG.

## Verification

1. Run the app with `npm run tauri dev`
2. Create a record with a valid URL → icon should display normally
3. Manually edit `data.json` to set an `iconUrl` pointing to a non-existent path → icon should show the default fallback
4. Records with `iconUrl: null` or `''` should continue showing the default fallback (no regression)
