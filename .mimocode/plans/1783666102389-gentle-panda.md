# Plan: Fix app update mechanism

## Root cause
Теги есть на remote (v0.2.0–v0.7.0), workflow успешные (2 запуска), но **релизов на GitHub нет** — API `/releases/latest` возвращает 404.

Updater (`updater.rs:28-35`) при 404 возвращает `has_update: false` → пользователь видит «у вас последняя версия».

Причина отсутствия релизов: `tauri-action@v0` не создал releases. Возможные причины:
- Secrets `TAURI_SIGNING_PRIVATE_KEY` / `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` не настроены
- Баг в `tauri-action@v0`
- `GITHUB_TOKEN` не имеет прав на создание releases

## Changes

### 1. Улучшить updater (`src-tauri/src/updater.rs`)
При 404 — показать пользователю ошибку вместо «последняя версия»:
```rust
if !response.status().is_success() {
    return Err(format!(
        "GitHub API returned {}. Check if releases exist at https://github.com/rudmion/MLocker/releases",
        response.status()
    ));
}
```

### 2. Добавить fallback: проверка по тегам через GitHub API
Если `/releases/latest` вернул 404, попробовать получить список тегов:
```
GET /repos/rudmion/MLocker/tags
```
И сравнить версию из самого свежего тега. Это позволит обнаружить обновление даже без релиза.

### 3. Обновить RELEASING.md
- Добавить секцию «Как проверить что релиз создался»
- Добавить инструкцию по ручному созданию релиза если workflow не создал его

## Files to modify
- `src-tauri/src/updater.rs` — fallback на tags API
- `RELEASING.md` — инструкции по ручному созданию релиза

## Verification
1. `curl https://api.github.com/repos/rudmion/MLocker/releases/latest` — должен вернуть релиз (или 404 если релизов нет)
2. `curl https://api.github.com/repos/rudmion/MLocker/tags` — должен вернуть теги
3. После правки updater: при 404 от releases — fallback на tags, обновление находится
