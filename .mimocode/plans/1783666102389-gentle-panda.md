# Plan: Windows Code Signing (SmartScreen)

## Проблема
Windows SmartScreen блокирует неподписанные исполняемые файлы. При скачивании установщика или запуске приложения появляется предупреждение «Windows защитила ваш ПК». Нужна Authenticode цифровая подпись.

## Почему это важно
- Без подписи SmartScreen показывает предупреждение при каждом скачивании
- Пользователи могут испугаться и не установить приложение
- EV-сертификат мгновенно получает репутацию у Microsoft
- OV-сертификат требует набора репутации (нужно чтобы люди скачивали и не жаловались)

## Вариант: SignPath (бесплатно для open-source)

SignPath предоставляет бесплатную кодовую подпись для open-source проектов. Подходит для MLocker так как репо публичный.

---

## Пошаговый план

### Шаг 1: Регистрация в SignPath

1. Открыть `https://signpath.org`
2. Нажать «Get Started» → «Free for Open Source»
3. Заполнить форму:
   - Organization name: `rudmion` (или ваше имя)
   - Project name: `MLocker`
   - Repository URL: `https://github.com/rudmion/MLocker`
   - Description: `Password manager built with Tauri`
4. Подтвердить email
5. Дождаться одобрения заявки (обычно 1-3 рабочих дня)

### Шаг 2: Получение сертификата

После одобрения SignPath:
1. Войти в dashboard SignPath
2. Перейти в «Code Signing» → «Certificates»
3. Скачать PFX файл
4. Запомнить пароль от PFX (он будет использоваться в GitHub Actions)

**Важно:** PFX файл содержит приватный ключ. Храните его в安全ном месте.

### Шаг 3: Конвертация PFX в Base64

GitHub Actions не может напрямую загрузить файл. Нужно закодировать PFX в Base64.

Открыть PowerShell на Windows:
```powershell
certutil -encode certificate.pfx base64cert.txt
```

Скопировать содержимое `base64cert.txt` — это и будет значение секрета.

### Шаг 4: Настройка GitHub Secrets

1. Открыть `https://github.com/rudmion/MLocker/settings/secrets/actions`
2. Нажать «New repository secret»
3. Добавить два секрета:

| Name | Value |
|------|-------|
| `WINDOWS_CERTIFICATE` | Содержимое base64cert.txt |
| `WINDOWS_CERTIFICATE_PASSWORD` | Пароль от PFX файла |

### Шаг 5: Обновление workflow

Файл: `.github/workflows/release.yml`

Добавить новый шаг **перед** «Install frontend dependencies» (только для Windows):

```yaml
      - name: Import Windows certificate
        if: matrix.platform == 'windows-latest'
        env:
          WINDOWS_CERTIFICATE: ${{ secrets.WINDOWS_CERTIFICATE }}
          WINDOWS_CERTIFICATE_PASSWORD: ${{ secrets.WINDOWS_CERTIFICATE_PASSWORD }}
        run: |
          New-Item -ItemType directory -Path certificate
          Set-Content -Path certificate/tempCert.txt -Value $env:WINDOWS_CERTIFICATE
          certutil -decode certificate/tempCert.txt certificate/certificate.pfx
          Remove-Item -path certificate -include tempCert.txt
          Import-PfxCertificate -FilePath certificate/certificate.pfx -CertStoreLocation Cert:\CurrentUser\My -Password (ConvertTo-SecureString -String $env:WINDOWS_CERTIFICATE_PASSWORD -Force -AsPlainText)
```

Этот шаг:
1. Создаёт папку `certificate`
2. Записывает Base64-encoded PFX в temp файл
3. Декодирует PFX из Base64
4. Удаляет temp файл
5. Импортирует PFX в хранилище сертификатов Windows

### Шаг 6: Получение Thumbprint

После импорта сертификата нужно получить его Thumbprint (отпечаток).

**Локально (для тестирования):**
1. Открыть `certmgr.msc`
2. Перейти в Personal → Certificates
3. Найти сертификат SignPath
4. Двойной клик → Details → Thumbprint
5. Скопировать значение (40 символов hex)

**В GitHub Actions (для проверки):**
Добавить временный шаг в workflow:
```yaml
      - name: Get certificate thumbprint
        if: matrix.platform == 'windows-latest'
        run: |
          $cert = Get-ChildItem -Path Cert:\CurrentUser\My | Where-Object {$_.Subject -like "*SignPath*"}
          Write-Host "Thumbprint: $($cert.Thumbprint)"
```

### Шаг 7: Настройка tauri.conf.json

Файл: `src-tauri/tauri.conf.json`

Добавить секцию `windows` в `bundle`:

```json
{
  "bundle": {
    "active": true,
    "targets": "all",
    "icon": ["..."],
    "windows": {
      "certificateThumbprint": "ВСТАВИТЬ_THUMBPRINT_СЮДА",
      "digestAlgorithm": "sha256",
      "timestampUrl": "http://timestamp.sectigo.com"
    }
  }
}
```

Параметры:
- `certificateThumbprint` — отпечаток сертификата из шага 6
- `digestAlgorithm` — алгоритм хеширования (sha256 — стандарт)
- `timestampUrl` — сервер времени для подтверждения момента подписи

### Шаг 8: Тестирование

1. Запушить изменения в `development`
2. Создать и запушить тег: `git tag v0.8.0 && git push origin v0.8.0`
3. Дождаться завершения workflow
4. Проверить логи — должно быть сообщение:
   ```
   info: signing app
   info: running signtool "C:\...\signtool.exe"
   info: "Done Adding Additional Store"
   info: Successfully signed: MLocker_0.8.0_x64-setup.exe
   ```
5. Скачать установщик из релиза
6. SmartScreen **не должен** показывать предупреждение

### Шаг 9: Обновить RELEASING.md

Добавить секцию о code signing:

```markdown
## Настройка Code Signing

Для подписи Windows-установщиков и устранения SmartScreen warning:

1. Зарегистрироваться в SignPath (бесплатно для open-source)
2. Получить PFX сертификат
3. Закодировать в Base64: `certutil -encode certificate.pfx base64cert.txt`
4. Добавить secrets в GitHub:
   - `WINDOWS_CERTIFICATE` — Base64 PFX
   - `WINDOWS_CERTIFICATE_PASSWORD` — пароль от PFX
5. Получить Thumbprint из certmgr.msc
6. Вписать Thumbprint в `tauri.conf.json` → `bundle.windows.certificateThumbprint`
```

## Verification

1. **Workflow**: После пуша тега workflow должен показать "Successfully signed"
2. **Установщик**: Скачанный файл не показывает SmartScreen warning
3. **Приложение**: Запущенное приложение не блокируется SmartScreen
4. **Updater**: Скачиваемый установщик не блокируется SmartScreen
