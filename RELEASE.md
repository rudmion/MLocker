# Релизный процесс MLocker

Полное описание того, как устроен релиз, как его выпустить, как описание релиза попадает к пользователю, как работает автообновление и как ротировать ключ подписи.

---

## 1. Как это устроено

### 1.1. Где хранится версия

Версия продублирована в четырёх файлах и должна совпадать везде:

| Файл | Поле |
|---|---|
| `package.json` | `"version"` |
| `src-tauri/tauri.conf.json` | `"version"` |
| `src-tauri/Cargo.toml` | `version = "..."` (первое вхождение, `[package]`) |
| `src-tauri/Cargo.lock` | блок `name = "manager-lock"` |

Версию вручную не правят — для этого есть интерактивный скрипт бампа.

### 1.2. Интерактивный скрипт бампа — `scripts/bump-version.cjs`

Запуск:

```bash
yarn bump            # полностью интерактивно
yarn bump 1.7.0      # версию можно передать аргументом, остальное спросит
```

Скрипт спрашивает пошагово:

1. **Версию** — показывает предыдущую версию и тег (`Текущая версия: 1.6.1 (тег v1.6.1)`), предлагает следующий patch по умолчанию (`[1.6.2]`). Поддерживается формат `X.Y.Z` и prerelease `X.Y.Z-beta.1`.
2. **Название релиза** — по умолчанию `MLocker v<версия>`.
3. **Описание релиза** — несколько строк (пустая строка завершает ввод): что было сделано в этом релизе.

Затем показывает сводку и просит подтверждение `(да/нет)`.

После подтверждения скрипт:
1. Проверяет, что рабочее дерево чистое (иначе просит сначала закоммитить изменения).
2. Обновляет версию во всех четырёх файлах.
3. Пишет `release-notes.json` (версия, тег, название, описание).
4. Коммитит `chore: bump version to X.Y.Z` (только файлы версии и release-notes.json).
5. Создаёт **аннотированный тег** `vX.Y.Z` (название и описание попадают в сообщение тега).
6. Пушит коммит и тег → CI запускается автоматически.

При ошибке git скрипт печатает команды для ручного выполнения.

Если stdin не TTY (запуск из скрипта), вопросы пропускаются: версия берётся из аргумента, название — дефолтное, описание пустое.

### 1.3. CI — `.github/workflows/release.yml`

Триггер: **push тега вида `v*`**.

Матрица сборок:

| Платформа | Runner | Target |
|---|---|---|
| Windows | `windows-latest` | `x86_64-pc-windows-msvc` |
| macOS | `macos-latest` | `aarch64-apple-darwin` |
| Linux | `ubuntu-22.04` | `x86_64-unknown-linux-gnu` |

Шаги каждого джоба:
1. checkout;
2. **`node scripts/release-meta.cjs`** — читает `release-notes.json`, передаёт `name` и `body` релиза в дальнейшие шаги (если файла нет или тег не совпадает с записанным — дефолтные значения);
3. Node.js 22 + Rust stable;
4. на Linux — apt-зависимости (`libgtk-3-dev`, `libwebkit2gtk-4.1-dev` и т.д.);
5. `yarn install`;
6. `tauri-apps/tauri-action@v0`:
   - собирает инсталляторы (`bundle.targets: "all"` из `tauri.conf.json`);
   - подписывает updater-артефакты приватным ключом;
   - создаёт GitHub Release `MLocker vX.Y.Z` **с названием и описанием из `release-notes.json`** (не draft, не prerelease);
   - прикладывает установщики + `.sig` + генерирует **`latest.json`** (манифест автообновления).

Секреты, используемые в workflow:

| Секрет | Назначение |
|---|---|
| `GITHUB_TOKEN` | автоматический, создаёт Release |
| `TAURI_SIGNING_PRIVATE_KEY` | приватный ключ подписи обновлений |
| `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` | пароль к приватному ключу |

### 1.4. `release-notes.json` — откуда описание берёт пользователь

`scripts/bump-version.cjs` записывает в корень репозитория:

```json
{
  "version": "1.7.0",
  "tag": "v1.7.0",
  "name": "MLocker v1.7.0",
  "body": "Что было сделано:\n- ..."
}
```

Файл коммитится вместе с бампом и дальше по цепочке:
1. CI читает его (`scripts/release-meta.cjs`) → название и описание уходят в GitHub Release;
2. приложение при находке обновления показывает это же описание пользователю (см. §1.6).

### 1.5. Автообновление в приложении

Конфиг — `src-tauri/tauri.conf.json`, секция `plugins.updater`:

- `pubkey` — публичный ключ, встроенный в приложение (проверяет подпись);
- `endpoints` — `https://github.com/rudmion/MLocker/releases/latest/download/latest.json`;
- `windows.installMode: "passive"` — тихая установка на Windows;
- `linux.installMode: "perUser"`.

Также `bundle.createUpdaterArtifacts: true` обязателен для генерации артефактов обновления.

Клиентская логика — `src/hooks/useUpdateChecker.ts`:

1. через 3 секунды после старта молча вызывает `check()` из `@tauri-apps/plugin-updater`;
2. если update найден — загружает описание релиза (см. ниже) и показывает уведомление с прогрессом;
3. `downloadAndInstall()` качает с прогресс-колбэком;
4. `relaunch()` (из `@tauri-apps/plugin-process`) перезапускает приложение;
5. «Позже» ставит snooze в `localStorage` на 2 дня.

### 1.6. Как описание попадает в уведомление об обновлении

`useUpdateChecker.fetchReleaseNotes()`:

1. сначала берёт `body` из манифеста обновления (`latest.json`), если он там есть;
2. иначе запрашивает GitHub API `GET /repos/rudmion/MLocker/releases/tags/v<версия>` и берёт `body` релиза;
3. при неудаче — описание просто не показывается.

Описание рендерится в `src/components/update/UpdateNotification.tsx` (блок «Changelog», многострочный текст с прокруткой) — пользователь видит его **до** нажатия «Обновить».

## 2. Как выпустить релиз (чек-лист)

1. **Закоммитить все изменения:**

   ```bash
   git status
   git add <файлы> && git commit -m "..."
   ```

   Скрипт бампа требует чистого рабочего дерево — он коммитит только файлы версии и `release-notes.json`.

2. **Проверить секреты GitHub** (однократно, при первой настройке):
   GitHub → репозиторий → **Settings → Secrets and variables → Actions** → должны существовать `TAURI_SIGNING_PRIVATE_KEY` и `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`.

3. **Запустить интерактивный релиз:**

   ```bash
   yarn bump
   ```

   Ответить на три вопроса (версия, название, описание) и подтвердить.

4. **Проверить прогресс:**
   - локально: версия обновлена в 4 файлах, `release-notes.json` создан, есть коммит и тег;
   - CI: https://github.com/rudmion/MLocker/actions → workflow **Release** идёт на 3 джоба (Windows/macOS/Linux).

5. **Дождаться релиза:** https://github.com/rudmion/MLocker/releases → появится `MLocker vX.Y.Z` с вашим названием, описанием и всеми установщиками. Описание увидят все, кто будет обновляться из приложения.

### Ручной запуск, если тег уже запушен

Если тег создан, но workflow не стартовал/упал — Actions → **Release** → **Re-run all jobs**.

## 3. Ротация ключа подписи

Ключ состоит из пары:
- **приватный** — подписывает артефакты, хранится только в секрете GitHub;
- **публичный** — вшит в `tauri.conf.json` → `plugins.updater.pubkey`, проверяется клиентом.

Менять нужно всегда **оба**.

### 3.1. Генерация новой пары

```bash
yarn tauri signer generate -w ~/.tauri/mlocker-key
```

Задайте пароль. Создадутся:
- `~/.tauri/mlocker-key` — приватный ключ;
- `~/.tauri/mlocker-key.pub` — публичный ключ.

### 3.2. Обновить публичный ключ

Вставить содержимое `.pub`-файла в `src-tauri/tauri.conf.json`:

```json
"updater": {
  "pubkey": "<содержимое mlocker-key.pub одним значением>",
  "endpoints": [ ... ]
}
```

### 3.3. Обновить секреты GitHub

В **Settings → Secrets and variables → Actions** заменить:
- `TAURI_SIGNING_PRIVATE_KEY` — **содержимое файла приватного ключа** (вместе с `-----BEGIN...`), а не путь к файлу;
- `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` — пароль от нового ключа.

### 3.4. Сохранить резервную копию

Скопировать `.key` и `.key.pub` в безопасное место (менеджер паролей, офлайн-носитель). При потере ключа и пароля подписать обновления невозможно — потребуется новая ротация.

### 3.5. Выпустить релиз новым ключом

```bash
yarn bump
```

### ⚠️ Последствия ротации

Старые клиенты содержат **старый** `pubkey` и **не смогут проверить** подпись обновлений, подписанных новым ключом — автообновление для них сломается. Поэтому:
- все, кто уже на версии с новым ключом, обновляются нормально;
- пользователям на старых версиях нужно предложить **ручную переустановку** с https://github.com/rudmion/MLocker/releases;
- ротацию делают только при компрометации/утере ключа и как можно реже.

## 4. Известные проблемы и план улучшений

### 🔴 Текущая проблема: рассинхрон версии

HEAD помечен тегом `v1.6.2`, но версии в файлах — `1.6.1` (тег поставлен вручную, без `bump`). Сборка v1.6.2 считает себя `1.6.1`, поэтому апдейтер будет вечно предлагать «обновление» до v1.6.2.

**Решение:** выпустить корректный релиз через `yarn bump` (например, 1.6.3) и перевыпустить.

## 5. Быстрая шпаргалка

```bash
# обычный релиз
git status          # дерево чистое? сначала закоммитить свои изменения
yarn bump           # вопрос 1: версия (показывает предыдущую и тег)
                    # вопрос 2: название релиза
                    # вопрос 3: описание релиза (что сделано)
                    # подтверждение → версии + release-notes.json + коммит + тег + пуш
# ждать Release на GitHub Actions → готово
# описание релиза увидят пользователи в уведомлении об обновлении

# ротация ключа подписи
yarn tauri signer generate -w ~/.tauri/mlocker-key
# pubkey → tauri.conf.json, приватник + пароль → GitHub Secrets
yarn bump
```
